What we built on

Twelve repositories, and what each one paid for

We read twelve open-source projects while building Disha. Every one of them either has a piece of our code tracing back to it, or a recorded reason we did not use it. Code was copied only from MIT-licensed projects — never from a project with no licence file, and never from an AGPL or GPL one. Ideas were taken more freely, and are labelled as ideas.

Remember

Spaced practicecode taken

A procedure you did once is not a procedure you can do in three weeks. Anything the learner masters gets a return date instead of being marked done forever.

Kept fsrs4anki (MIT) because it is the algorithm behind the strongest evidence we cite — spaced retrieval, g = 0.74 — and porting it turns a claim on a slide into behaviour in the product.

Lands in lib/remember.js. Measured, reviewing on each due date: 2 → 11 → 46 → 163 → 365 days; one wrong click collapses it back to 7.

Privacy

Masking values before they leave the deviceidea only

Our architecture diagram promises that only control names leave the device. A badly built portal puts the value into the name — so a field can carry an Aadhaar number into the prompt. Now it cannot.

Idea from ai-page-assist, no code. That project has no licence file, so nothing was copied; we re-implemented the idea ourselves. Aadhaar, PAN, email, mobile, bank account, card and OTP are masked in place.

Lands in lib/redact.js. The mask keeps the shape — Aadhaar «aadhaar» linked — because the model still has to tell an Aadhaar field from a phone field; it just never sees the digits.

Guide — the core

Finding controls that are not really controlsidea only

Many real controls are plain <div>s that announce themselves only through cursor:pointer. We were blind to every one.

Kept the heuristic from browser-use (MIT); wrote our own implementation — computed style, skipping wrappers that already contain a real control, capped at 40 additions. We deliberately did not take its autopilot clicking.

Lands in lib/tree.js. Controls found, before → after: our demo 27 → 27 · scholarships.gov.in 28 → 31 · swayam.gov.in 50 → 70 · aicte-india.org 119 → 120. Zero on our own mock, because it is built from real buttons — the heuristic earns its keep on the sites our users actually face.

Drawing the markeridea only

A marker has to follow an element that moves, resizes and disappears.

Reviewed element-highlighter (MIT), VisualTagger (no licence) and chrome-element-inspector (GPL). The live-rect + MutationObserver lifecycle was already ours, so nothing was taken. We dropped absolute document coordinates, which break the moment a page scrolls.

See — the fallback we have not built

Vision groundingnothing taken yet

When a control has no accessible name at all, reading the page cannot help and only pixels remain. This is on the roadmap, not in this build, and we say so on the slide.

Chose GUI-Actor (MIT) over OmniParser — OmniParser's icon detector is AGPL, and GUI-Actor returns a verifier score per region, which maps onto the model half of our two-number rule without changing the colour bands at all. A pixel-sourced dot would be capped at amber and badged "from pixels", the same discipline that caps the offline matcher today.

Tour — reviewed and rejected

Authored walkthroughsnot taken

intro.js and shepherd are both AGPL, so their code was never an option. Two reasons beyond the licence: every step must be authored in advance for one specific product, and both scroll the page for the user. We point with an arrow and let the person scroll — being driven teaches nothing.

Captureout of scope

meeting-minutes and open-notebook (both MIT) were candidates for a note-taking module in the portal. Out of scope for the intercollege build; recorded so the decision is not re-made from scratch later.
